 🟦 1. Технический сценарий работы модуля авторизации

Ниже описана логика работы всей системы авторизации — от отправки кода до проверки токена.

 🔹 Шаг 1. Пользователь запрашивает код

Маршрут:  
POST /oauth/code

Процесс:
- Пользователь отправляет свой идентификатор (например, Telegram ID).
- Генерируется 6‑значный код.
- Код сохраняется в in‑memory хранилище (storage.go) с TTL.
- Код отправляется пользователю через Telegram‑бота (telegram.go).

 🔹 Шаг 2. Пользователь вводит код

Маршрут:  
POST /oauth/verify

Процесс:
- Пользователь отправляет код.
- Модуль проверяет:
  - существует ли код
  - не истёк ли срок
  - совпадает ли код
- Если всё корректно — пользователю разрешается получить токен.

 🔹 Шаг 3. Генерация токенов
Маршрут:  
POST /oauth/token
Процесс:
- Генерируется access‑token (короткий срок жизни).
- Генерируется refresh‑token (долгий срок жизни).
- Refresh‑token сохраняется в storage.go.
- Пользователь получает оба токена.

 🔹 Шаг 4. Обновление токена

Маршрут:  
POST /oauth/refresh
Процесс:
- Пользователь отправляет refresh‑token.
- Модуль проверяет:
  - существует ли он
  - не истёк ли срок
- Генерирует новый access‑token.

   🔹 Шаг 5. Доступ к защищённым маршрутам

Маршрут:  
GET /profile

Middleware проверяет:
- наличие токена
- подпись JWT1
- срок действия
- роль пользователя

Если всё корректно — запрос проходит дальше.

 🔹 Шаг 6. Фоновая очистка
 
В main.go запускается таймер, который каждые 60 секунд удаляет:

- просроченные коды
- просроченные refresh‑токены
- просроченные попытки

 🔹 Основная идея

«Пользователь вводит свой идентификатор, получает код в Telegram, подтверждает его и получает пару токенов — access и refresh. Access‑токен используется для доступа к защищённым маршрутам, а refresh‑токен позволяет обновлять сессию.»

 🔹 Что реализовано мной

- Генерация и проверка кодов  
- Отправка кода через Telegram‑бота  
- Генерация JWT‑токенов  
- Хранилище для кодов, токенов и ролей  
- Middleware для проверки токена  
- Очистка устаревших данных  
- Полный набор API‑маршрутов  

🔹 Архитектура проекта

- main.go — запуск сервера и фоновые задачи  
- handler.go — обработка запросов  
- jwt.go — генерация токенов  
- middleware.go — защита маршрутов  
- storage.go — in‑memory хранилище  
- telegram.go — отправка кода  
- permissions.go — роли и права
